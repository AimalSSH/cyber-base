# API Fuzzer - Мутационный фаззер для REST API

Мутационный фаззер для REST API эндпоинтов. Генерирует "интересные" payload'ы на основе seed JSON и сохраняет их для дальнейшего анализа.

## Отказ от ответственности

Данный инструмент предназначен для образовательных целей и тестирования систем, где у вас есть явное разрешение на проведение таких тестов. Использование фаззера против систем без согласия владельца может нарушать законы о компьютерной безопасности. Автор не несет ответственности за неправомерное использование.

## Описание

Данный скрипт реализует мутационный фаззер для REST API, который:
- Принимает эталонный JSON payload (seed)
- Генерирует мутированные версии путем изменения полей
- Отправляет запросы к целевому эндпоинту
- Анализирует ответы на предмет "интересных" аномалий
- Сохраняет подозрительные payload'ы для ручного триажа

## Примеры использования

1. Запуск с параметрами по умолчанию:
```bash
python api_fuzzer.py
```

2. Фаззинг конкретного эндпоинта:
```bash
python api_fuzzer.py -t http://localhost:3000/api/v1/users -s seed.json
```

3. Детальный лог с сохранением всех интересных payload'ов:
```bash
python api_fuzzer.py -t https://api.example.com/v1/test -v -o crash_reports -n 500
```

4. Только логирование, без сохранения файлов:
```bash
python api_fuzzer.py -t http://localhost:8080/endpoint --no-save --verbose
```

5. Кастомные ключевые слова для поиска:
```bash
python api_fuzzer.py -t http://localhost:3000/api -s seed.json --keywords "SQL syntax mysql_fetch_array warning"
```

## Как это работает

Скрипт выполняет следующие шаги:
1. Загрузка seed: Читает эталонный JSON payload из файла
2. Измерение baseline: Отправляет 5 запросов с seed payload для определения базового времени ответа
3. Мутация: Для каждой итерации случайным образом мутирует одно поле:
    - Строки: заменяет на пустую строку, добавляет 200-2000 символов или вставляет null-байт с не-ASCII символами
    - Числа: подставляет 0, -1, 2³¹-1, 2⁶³-1 или -2³¹
    - Списки: добавляет длинную строку в конец
    - Другие типы: заменяет на null
4. Отправка запроса: Выполняет POST запрос с мутированным payload
5. Анализ ответа: Проверяет на "интересность" по критериям
6. Сохранение: Сохраняет интересные payload'ы в отдельные JSON файлы с метаданными

## Критерии "интересного" запроса
Скрипт помечает запрос как интересный, если:
- HTTP статус 500+ (внутренняя ошибка сервера)
- Медленный ответ (> baseline × SLOW_FACTOR)
- Ключевые слова в теле ответа (exception, error, traceback и др.)
- Ошибки сети (таймаут, отказ соединения)

## Формат вывода
Скрипт выводит:
- Прогресс выполнения с указанием номера итерации
- Статус запроса (INTERESTING/OK)
- Код ответа и время выполнения
- При verbose-режиме - полный payload интересных запросов

## Структура отчета
Каждый сохраненный файл содержит:
```json
{
  "meta": {
    "index": 42,
    "code": 500,
    "rt": 2.345,
    "reasons": ["http_500", "body_contains_exception"],
    "target": "http://localhost:3000/api"
  },
  "payload": {
    "rating": -1,
    "comment": "\x00...",
    "user": "test_user"
  }
}
```
Пример seed.json

```json
{
  "rating": 5,
  "comment": "Great product! Very satisfied.",
  "user": "test_user",
  "tags": ["electronics", "gadget"]
}
```
### Обработка ошибок
Скрипт обрабатывает следующие ошибки:
- Отсутствие seed файла - завершение с сообщением об ошибке
- Невалидный JSON - завершение с указанием ошибки парсинга
- Таймауты соединения - помечаются как интересные (network_error)
- Ошибки DNS/сети - логируются как ошибки соединения
- Некорректные ответы сервера - обрабатываются и логируются

Примечания
- Для воспроизводимости используется фиксированный seed (по умолчанию 42)
- Все интересные payload'ы сохраняются с временной меткой для избежания перезаписи
- Тело ответа обрезается до 2000 символов для экономии памяти
- Поддерживаются только POST запросы (легко адаптировать под другие методы)
- Для увеличения покрытия рекомендуется запускать несколько раз с разными seed-значениями
- Нагрузка на сервер может быть значительной - используйте с осторожностью
